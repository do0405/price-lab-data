# Encrypted daily price changes

The cloud is a stateless collector. It does not create, restore, cache, publish, or retain a DuckDB database. The research application's single canonical DuckDB, historical archives, split adjustments, security history, validation, and backtests remain local. No periodic full backup is scheduled.

## Schedule and access

The main-branch workflow collects all markets at 10:30 and 20:37 Asia/Seoul, including weekends for crypto. Korea-only availability checks run on weekdays at 15:37, 15:52, 16:07, 16:22, 17:07, 18:07 and 19:07 Seoul time. GitHub may delay scheduled runs. A serialized check at minute 17 every six hours UTC verifies the latest encrypted package without collecting prices or opening a database.

Credentials belong only in existing Actions Secrets: ALPACA_API_KEY, ALPACA_API_SECRET, KRX_API_KEY, KIS_APP_KEY, KIS_APP_SECRET, PRICE_DATA_KEY. The data key is a random 32-byte URL-safe base64 key. No broker account identifier is needed. Trusted main-branch scheduled/manual runs alone receive secrets; checkout does not persist credentials.

SEC requests additionally require the existing declared bot identity in `SEC_USER_AGENT`, including a real contact address. It is sent only to SEC, never to other reference providers. The local bridge protects that setting with Windows DPAPI and the operator registers it as an Actions Secret; identity values and raw denial pages are not logged or exported. A bounded SEC denial diagnostic retains only status, fixed classification and body fingerprint. The default denied-host cooldown stays intact. Explicit local identity recovery probes each affected official host once and resumes only a host whose actual response passes its source contract. Manual Actions can select the SEC-only source scope to verify cloud access without changing the six-hour schedule.

The cloud runtime and its CI use requirements-delta.txt, which contains no database engine. Database-based application regression tests run locally. CI uses only DB-free codec, collection, and entrypoint contract tests.

After 25 days without main-branch activity, a successful trusted run may update `.github/price-pipeline-status.json` with package identity, watermarks and validation time. This is not an uptime guarantee.

## Collection and transfer

Alpaca supplies US/crypto bars, KRX supplies Korean daily bulk bars, and KIS supplies Korean benchmark bars and corporate-action observations. Each collection requests missing sessions plus the latest five completed sessions to discover corrections. A Sunday audit rechecks one bounded historical window of at most twenty sessions per market, advancing its control cursor. It never downloads a historical database. There is no rolling deletion at 750 sessions.

The first run verifies the HMAC on config/daily-bootstrap.json. This small non-DB control contains a preserved local anchor identity, observed symbol directory, actual completed-session labels, watermarks, and calendar evidence. Later runs obtain this state from the latest authenticated package. The control is not a price database or a historical investment universe.

Each immutable Release contains only daily.pldelta: canonical JSON records compressed with gzip and encrypted/authenticated with AES-256-GCM in a separate PLDELTA1 domain. Schema, stream, sequence, predecessor package hash, local bootstrap anchor, and collection time bind the records. Header size is bounded at 4KiB and uncompressed payload at 512MiB. Authentication completes before JSON parsing or decompression. Packages contain raw bars, asset observations, corporate actions, requested/completed sessions, action-query boundaries, and bounded official Korean capitalization/security-master responses. API keys and authorization headers are forbidden fields.

A package is made ready only after the encrypted asset is uploaded. A failed price/action/required-benchmark request does not advance collection state. Reference failures have a separate fixed status and do not erase successful price collection. Reference dates and retrieval times do not certify historical publication timing or complete security lifecycles.

Korean KRX daily collection becomes eligible at the exchange's scheduled session close. Both KOSPI and KOSDAQ must return nonempty rows for the requested date. An explicitly empty board is retried after 5, 20 and 60 seconds. If the board stays empty, the date remains pending for a later run and prior authenticated prices stay available. Weekday checks start at 15:37 Seoul time and retry during the evening. These checks only collect missing Korean sessions and publish a package when at least one is ready. Regular all-market runs continue overlap and historical corrections. The same encrypted package, ciphertext hash and predecessor verification apply throughout.

## Local application

The local app downloads missing packages in sequence, verifies ciphertext/content identity and continuity, and applies them to a copy of its freshest local parent. The existing raw-preserving ingestion and split-confirmation rules build the next immutable DuckDB. All parts are staged before corporate actions are evaluated; a later package can supply the evidence needed to resolve an earlier unconfirmed action. Applied-package receipts and the resulting data commit together only after validation. Tampering, gaps, unconfirmed actions, or database validation failures leave the prior app database and cursor intact. Exact replays are no-ops.

US/crypto turnover is provider VWAP times volume; Korean turnover is the provider's actual traded value. Split-adjusted turnover is value invariant. KSD record dates are not treated as execution dates, and price jumps do not manufacture split factors. Ordinary dividend reinvestment and complete historical security lifecycles are outside this split-only price contract.

A PC that was off catches up from retained encrypted packages when it next starts. Local-only unfinished backfills cannot be read while that PC is off. They are validated and merged locally on the next six-hour pass; complete candidate databases are never uploaded. Collection success and local application success are separate states.

Existing full-checkpoint Releases belong to the retired transport and are removed only after local preservation and migration validation. There is no automatic fallback to them. Do not prune daily packages automatically: a missing package breaks catch-up for offline clients. A new device needs a locally preserved baseline; the cloud contains no baseline database. Protect the encryption key independently.


## Continuous Korean reference and disclosure collection

`reference-evidence.yml` continues bounded raw-source batches automatically. It uses the same existing Actions Secrets, an independent authenticated encrypted research delta stream, and a small HMAC/CAS request reservation journal. No DuckDB, database cache, full snapshot or backup is created in Actions. The encrypted bootstrap contains only portable acquisition tasks/control and source hashes.

Each job runs at most 330 minutes of production, publishing closed batches immediately and continuing the next batch. Eligible jobs request one successor; the ten-minute schedule is recovery, and GitHub schedules may be delayed. Actual-time price windows and shared queued concurrency protect the existing daily price jobs. The operator removed artificial daily request budgets on 2026-10-16. Collection continues while work remains, with per-provider spacing and persisted HTTP/Retry-After waits. All HTTP sends, including OAuth, retain prior durable accounting; crashes never erase request reservations. Bounded chunks limit memory and renew ownership, without imposing a daily collection allowance.

The local application authenticates contiguous packages, retains immutable source bytes, validates references and unknown lifecycle observations, and atomically updates its managed local database. Raw acquisition does not approve security identity, adjustment ratios, actual settlement amounts or publication-time validity. Local baseline data remains required; the cloud stream is not a full restoration backup.

Local catch-up completes every selected package download and authentication before opening its database transaction. Authenticated ciphertext is cached by its immutable hash so a transient network failure reuses the completed prefix. Database application then decodes local packages sequentially, without download workers retaining decoded lookahead. Selected ciphertext is removed only after its receipt sequence is committed; an authentication or local mutation failure preserves the staged inputs and the old cursor. This local cache is separate from the durable encrypted Releases, which remain available for offline catch-up.

Request totals remain durable. The journal retains the latest 1,024 request identities for immediate uncertain-write confirmation. Reusing an older evicted identity conservatively adds to accounting again; it never replays an HTTP request. Each actual source execution uses a fresh identity.

## Local-first historical acquisition

An enabled private PC controller collects every unfinished supported local historical plan, including original price archives, reference/master records, metadata, corporate-action evidence, crosschecks and disclosure originals. Existing complete source scopes do not request their history again. Private paths, provider credentials, controller code and databases are not exported here.

The shared research collector uses a signed, small `.github/research-owner.json` control with a local preference, expiring acquisition lease, monotonic epoch and canonical package head. Local and Actions producers reuse the same authenticated research state and durable quota journal. An active local producer has preference; after PC loss the expiring lease permits Actions to resume. A ready encrypted release is accepted only if the live owner CAS-commits its exact parent/hash as the canonical head. Uncommitted orphan branches are preserved but excluded from local application. The existing daily-price stream and its schedule stay independent.

## Official index, industry and share references

`market-references.yml` runs every six hours, with manual bounded runs available. It collects official iShares holdings/sector snapshots, KIND industry observations, KRX index series, FRED price-index series, Cboe VIX/VVIX history, S&P change notices, LSEG/Russell notices and SEC share/submission references. Historical cursors and current refreshes are checkpointed; unchanged response bytes are not repeatedly delivered. Missing, denied and malformed sources stay explicit gaps with scoped retries.

The `market-reference-v1` encrypted stream uses the existing data key and a separate signed `.github/market-reference-owner.json` lease/head. It does not reset Korean research or price collection. Actions creates no database. Public CIK seeds are identifiers, not a historical security universe. The local `queue-issuers --local` operator recovers missing issuer identifiers from already retained official share-count observations. New seeds append to the existing list so persisted scan positions remain stable; current-directory omissions do not silently discard historical issuers. ETF holdings remain proxies; announcements are not approved daily constituents, SIC/provider/GICS classifications stay distinct, and current or retrospectively queried values do not certify original PIT availability.

The same collector now follows LSEG's public constituent-weight catalog for Russell 1000/2000/3000 and their growth/value reports, published Russell IPO lists, Citi depositary corporate-action notices and their explicitly linked attachments, a verified public BNY exchange notice, and FINRA's date-filtered OTC Daily List. No additional credentials are configured for these public sources. Older denied endpoints remain gaps; another successful source never clears their authorization cooldowns.

The public ADR directory and corporate-action API used by JPMorgan's adr.com is also collected with exact 1,000-row pagination. Directory values are current observations: provider global market capitalization and price do not establish a historical share-class valuation, currency, ADR quote unit or investment universe. Reported action dates, document IDs and revision sequence numbers are retained; a Final label does not approve final settlement or historical publication time. The directory and every subsequent page are rechecked daily through the existing schedule. Case-normalized CUSIPs retain their original raw spelling; malformed short identifiers remain unlinked and are never padded. Empty action names remain unknown. Identical duplicate rows are normalized once while the original response remains in the encrypted package.

Bootstrap v4 preserves the original CIK, dated fund targets and Citi attachment IDs and adds bounded public JPMorgan document/revision IDs recovered from retained authenticated catalogs. Ratio changes, terminations, exchanges and selected capital actions follow only their explicitly linked public PDF IDs. Covers and catalogs are not refetched just to rediscover their links. New covers discover attachments automatically; unchanged covers also permit a monthly attachment recheck. Pinned JPMorgan revisions are rechecked monthly while directory pages refresh daily. Attachment work has priority within the ADR lane, while every fifth request leaves room for other reference categories. FINRA empty-day 204 responses are recorded as source-empty, not as invented events or host denials. Historical work resumes from signed cursors.

Quarterly reports expose rounded weights and may identify constituents only by name. A preliminary addition, a reported ADR ratio, an indicative net cash rate or an OTC ticker change is source evidence, not approved historical membership, quote units, final account entitlements or strict PIT. The local receiver retains those boundaries and source clock/version uncertainty.

The private local receiver authenticates the chain, normalizes typed inputs and uses the existing single-database atomic publication/roundtrip. It preserves closed inputs and reports `WAITING_DISK_SPACE` when the volume cannot hold the private working copy. Collection success never implies local database publication success.
